# Проверки чистовой версии

Перед публикацией submission-v1 выполнены **143 теста Django, 105 HTTP-проверок и 5 тестов JavaScript**. Python-проверки и настоящий Gunicorn работают внутри Docker на временных базах. Рабочая база не используется. Проверки конфигурации, миграций, зависимостей и production-настроек также проходят.

## Повторный запуск

Из корня репозитория:

```sh
sh scripts/check.sh
```

Нужны Docker Compose и POSIX shell (Linux/macOS/WSL). Скрипт собирает образ, монтирует тесты и независимый эталон модели только для проверок, запускает серверные тесты, а затем `scripts/check_http.py`. Этот помощник создаёт временную базу с синтетическими данными, запускает настоящий Gunicorn на свободном порту внутри контейнера и выполняет `tests.live_http`. После проверки сервер останавливается, временные данные удаляются. Секреты не печатаются и не попадают в исходники.

Для пяти тестов JavaScript нужен установленный Node.js; npm-пакеты не нужны. Если Node.js отсутствует, скрипт явно сообщает, что эти тесты пропущены. На запуск сайта это не влияет. Для submission-v1 JavaScript-тесты выполнены.

Для отдельного запуска серверных тестов используйте Docker-команду из [README](../README.md#проверки-через-docker). Для проверки конкретного сценария через HTTP используйте отдельную демобазу: прогон создаёт заявки и принимает предложения. Не направляйте `tests.live_http` на рабочую базу.

Покрытие строк, нагрузка, визуальный браузерный аудит и WCAG не измерялись. Проверки версии для сдачи перечислены в [release-checks.md](release-checks.md).

## Состав проверок

- `tests/test_cabinet.py`: кабинеты, заявки, документы, роли, CSRF и полный цикл.
- `tests/test_domain.py`: денежные расчёты, аннуитетный график и переходы статусов.
- `tests/test_audit.py`, `tests/test_hardening.py`: чужие объекты, устаревшие формы, подмена роли, лимиты и повторная отправка.
- `tests/test_scorecard.py`, `tests/test_scorecard_workflow.py`: контракт JSON, обе финансовые ветки, стоп-факторы, лимит, решение и принятие условий.
- `tests/test_security_inputs.py`: дублирующиеся ключи, неоднозначные алиасы, дробные копейки, повреждённый JSON, ошибочные типы, XSS, SQL-строки и актуальность проверок.
- `tests/test_configuration.py`: обратная совместимость настроек без отключения HTTPS.
- `tests/frontend.test.cjs`: устаревшие ответы калькулятора, потеря сети, неверные поля и переключение решения.
- `tests/live_http.py`: реальный HTTP, сессии и CSRF, изоляция клиентов, конкурирующие POST, документы и статические ресурсы.

- `tests/test_automatic_decisions.py`: полная модель при обычной отправке, серая зона, актуальность источников и история.
- `tests/test_mlcard_reference.py`: побайтовая сохранность оригинала в `docs/reference/mlcard`, совпадение результатов обеих веток и границы PD.

- `tests/test_upload_submission.py`: общий multipart-form для файла и отправки, загрузка за один шаг, сохранение вложения при ошибках, правильный тип документа, отсутствие дубликатов и защита от устаревших версий.

- `tests/test_security_review.py`: свежесть и принадлежность скоринга, привязка к снимку заявки, запрет старых/демонстрационных оферт, неоднозначный JSON, длинные пароли и запрет production DEBUG.
